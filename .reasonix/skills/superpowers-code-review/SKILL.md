# 代码审查

## 概述

使用 Reasonix Code 的 `review` 工具派发代码审查子代理，在问题扩散之前捕获它们。

**核心原则：** 早审查，常审查。

## 何时请求审查

**强制：**
- 完成主要功能后
- 合并到主分支前
- 在 `superpowers-executing-plans` 中完成一组任务后

**可选但有价值：**
- 卡住时（新鲜视角）
- 重构前（基线检查）
- 修复复杂 bug 后

## 如何请求

使用 Reasonix Code 的内置 `review` 工具：

```
review({ task: "审查最近变更，聚焦于 <具体关注点>" })
```

`review` 工具会自动检查当前分支的 diff，标记：
- 正确性问题
- 安全漏洞
- 缺失测试
- 隐藏行为

## 响应反馈

- **严重问题（Critical）：** 立即修复
- **重要问题（Important）：** 在继续前修复
- **小问题（Minor）：** 记录，稍后修复
- 如果审查者错了，用技术推理反驳

## 集成工作流

- 在 `superpowers-executing-plans` 中完成一组任务后调用审查
- 在 `superpowers-finishing-branch` 中合并前调用审查
- 在提交较大变更集后调用审查

## 红旗信号

**永远不要：**
- 因为"简单"而跳过审查
- 忽略严重问题
- 带着未修复的重要问题继续
- 与有效的技术反馈争论

**如果审查者错了：**
- 用技术推理反驳
- 展示证明它工作的代码/测试
- 请求澄清
